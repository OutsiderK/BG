# 折维圣徒版本迭代总路线图

这份路线图用于把当前 Godot 原型从“能运行的技术 demo”推进到“可反复试玩、能验证核心卖点的 roguelike demo”。每个版本都按一个明确问题推进，避免同时扩太多系统。

## 当前基线

- 分支：`feat/demo-v0-integration`
- 状态：Godot 工程可运行，巨木薄林单房间可进入，v0.1 手感闭环、v0.2 展开可读性、v0.3 美术与武器切片已集成。
- 已有：玩家移动、跳跃、冲刺、剑攻击逻辑与剑击弧光、薄林敌人视觉、敌人基础追击/攻击预警、受击/死亡锁定、命中反馈、相机跟随、圣痕热度、平面展开/坍缩过渡、lane/落点提示、美化 HUD、Windows 同步脚本。
- 主要缺口：房间目标、清场/撤离/结算流程、内容池、存档元进度、主角与敌人的进一步美术 polish。

## 版本节奏

| 版本 | 名称 | 核心问题 | 完成标准 |
| --- | --- | --- | --- |
| v0.1 | 手感闭环 | 打起来是否清楚、可控、有反馈 | 已集成：玩家可完成一场 2-3 敌人的小战斗，受击和命中都能读懂 |
| v0.2 | 展开可读性 | 核心机制是否一眼能看懂 | 已集成：展开/坍缩有过渡、落点、风险反馈，俯视规则不混乱 |
| v0.3 | 美术与武器垂直切片 | demo 是否摆脱灰盒感并动得足够顺 | 确定 AI sprite sheet + AnimatedSprite2D 管线，主角、敌人、剑、房间、HUD、展开 FX 有统一风格 |
| v0.4 | 单局流程 | demo 是否有开始、目标和结束 | 锁门、清场、撤离、结算形成 3 分钟闭环 |
| v0.5 | 构筑雏形 | roguelike 选择是否开始成立 | 至少 1 武器、8-12 道具、3 个构筑方向可测试 |
| v0.6 | 区域扩展 | 房间与敌人是否能撑起重复游玩 | 5-7 个房间、3 类敌人、1 个精英/小 Boss |
| v0.7 | 元进度与存档 | 死亡和成长是否形成长期驱动 | 圣徒之路、撤离保存、死亡结算、锚率风险跑通 |
| v0.8 | 公开试玩版 | 是否能给外部玩家试玩 | 菜单、音量、暂停、键位提示、bug 收敛、导出包 |

## 版本门槛

每个版本必须满足：

- `python3 tools/verify_scaffold.py` 通过。
- Godot headless smoke test 通过。
- Windows 分支同步后可以运行。
- 新增机制有最少一个可复现验收步骤。
- 合并前记录已知问题，不把“未完成体验”伪装成完成。

## v0.1：手感闭环

状态：已集成到 `feat/demo-v0-integration`。

目标：让当前单房间战斗从“能碰撞”升级为“能判断手感方向”。

范围：

- 玩家受击反馈、无敌反馈、死亡输入锁定。
- 敌人攻击前摇可读、攻击窗口清晰。
- 命中反馈：命中停顿、击退、伤害数字或临时视觉。
- 相机跟随和基础屏幕震动。
- 继续保留当前单房间，不扩内容池。

不做：

- 不新增第二把武器。
- 不新增道具系统。
- 不做正式美术。
- 不做完整结算。

通过标准：

- 玩家可以和当前房间内敌人打一场完整战斗。
- 玩家被打中前能看到预警。
- 玩家打中敌人有明确命中反馈。
- 玩家死亡后不能继续移动/攻击。
- 相机能跟随玩家，不出现主要战斗区域离屏。

## v0.2：展开可读性

状态：已集成到 `feat/demo-v0-integration`。

目标：把核心卖点“平面展开”做成玩家能理解的体验，而不是只有状态切换。

范围：

- 展开进入/退出过渡表现。
- 展开状态移动规则提示与 HUD 状态变化。
- lane/落点反馈。
- 坍缩后位置吸附反馈。
- 锚率/灾厄侵蚀变化的 UI 提示。

通过标准：

- 玩家第一次按 `1` 后能看懂空间规则变化。
- 坍缩后玩家和敌人不会悬空、穿墙或不可达。
- 展开风险变化在 HUD 上明确可见。

## v0.3：美术与武器垂直切片

状态：已集成到 `feat/demo-v0-integration`。

目标：先把当前 demo 从灰盒工程提升到有统一风格、动画流畅的可展示切片，并让剑等武器从“数据和命中盒”变成玩家能看见、能理解的战斗对象。

详细方案：[iterations/v0.3_art_weapon_vertical_slice.md](iterations/v0.3_art_weapon_vertical_slice.md)。
动画工具链：[art/animation_pipeline.md](art/animation_pipeline.md)。

范围：

- 确定第一版美术方向、调色板、资源命名、动画工具链和目录。
- 建立 AI sprite sheet/Godot 兼容的动画包装层和事件桥接方案。
- 替换主角方块表现，加入基础人形轮廓、影子、受击/冲刺/死亡视觉。
- 加入武器挂点和剑的可见模型/挥砍弧/命中特效。
- 为矛、弓、法杖、回旋刃、圣铃建立图标或展示占位，保留后续玩法入口。
- 替换巨木薄林房间的主要灰盒表现，让地形、背景、lane 提示和出口占位统一。
- 统一 HUD 的生命、热度、锚率、当前武器显示。

不做：

- 不实现 6 把武器的完整玩法切换。
- 不新增正式结算、商店、道具选择。
- 不扩房间数量。

通过标准：

- 主场景截图中不再像调试场景，玩家、敌人、地形、HUD、展开提示信息层清楚。
- 20 秒战斗片段中，跑动、冲刺、剑击、受击、展开、坍缩没有明显卡顿或挂点漂移。
- 玩家攻击时能看到剑和挥砍弧，命中反馈和命中盒方向一致。
- `1` 展开后的 lane/落点提示融入世界视觉，而不是纯临时线。
- 现有 smoke tests 不因美术改动失败。

## v0.4：单局流程

目标：让 demo 有一个能结束的目标。

范围：

- 房间进入锁门。
- 清场后开启撤离点。
- `E` 交互撤离。
- 简易结算界面：击杀、展开次数、锚率变化、获得圣痕点。

通过标准：

- 玩家从出生、战斗、撤离、结算能完整走完一次。
- 中途死亡和成功撤离各有明确结果。

## v0.5：构筑雏形

目标：开始验证 roguelike 的“选择乐趣”。

范围：

- 道具选择界面占位。
- 8-12 个可实现道具。
- 至少 3 个构筑原型：冲刺连段、暴击堆叠、展开收益。
- 道具数据配置化。

通过标准：

- 一局内至少出现 2 次选择。
- 不同选择能明显改变战斗方式。

## v0.6：区域扩展

目标：让巨木薄林从单房间变成小区域。

范围：

- 5-7 个房间模板。
- 3 类普通敌人。
- 1 个精英或小 Boss。
- 房间连接和最小随机路线。

通过标准：

- 单局可以连续通过 4-6 个房间。
- 不同房间组合下展开机制仍可用。

## v0.7：元进度与存档

目标：验证“死亡风险 + 长期成长”是否成立。

范围：

- 圣徒之路节点。
- 圣痕点结算与保存。
- 锚率风险保存。
- 中途退出/区域间继续的基础存档。

通过标准：

- 死亡、撤离、重开后数值状态符合设定。
- 彻底死亡风险可以显示和结算。

## v0.8：公开试玩版

目标：整理成能发给外部玩家的版本。

范围：

- 主菜单、暂停、设置。
- 音量和键位提示。
- 导出配置。
- 已知 bug 清单和试玩反馈表。

通过标准：

- Windows 导出包可运行。
- 外部玩家无需开发环境即可试玩。
