# v0.3 美术与武器垂直切片

状态：规划完成，等待开工。

## 目标

当前 demo 已经能跑通移动、战斗、展开和 HUD，但画面仍是灰盒感，武器也只有命中盒，没有“玩家正在挥剑”的视觉事实。v0.3 的目标是先把一个房间做成可展示的垂直切片：玩家、敌人、剑、场景、HUD 和展开效果都要有统一风格，并且角色与武器动画必须朝高质量、流畅、可扩展的管线走。

本轮不要求完成最终全套商业资产，也不把 6 把武器全部做成完整玩法。但本轮必须确定动画工具链，不能只用临时图形节点拼“能动”的效果。高规格动画方案见：[../art/animation_pipeline.md](../art/animation_pipeline.md)。

## 美术定位

关键词：

- 二维封印世界：空间像被压成纸页，边缘有折痕、切线、错层。
- 圣徒残响：主角不是华丽骑士，而是被坐标钉住的无名执行者，轮廓克制、动作干净。
- 巨木薄林：第一房间要像一片被压薄的森林切片，树干、枝台、根墙都是“可读的地形”。
- 灾厄侵蚀：不要只用红黑污染，优先用坐标噪声、线条错位、局部透明、裂纹扩散表达。
- 武器即构筑入口：每把武器从剪影、攻击轨迹和 UI 图标上就要能区分玩法倾向。

视觉优先级：

1. 可读性高于细节。玩家、敌人、武器、危险预警、可站立地面必须在 720p 下清楚。
2. 动作反馈高于静态精度。挥剑轨迹、命中火花、受击闪烁比精修立绘更重要。
3. 流畅动画高于静态精修。角色、敌人和武器必须建立可复用骨骼/事件帧管线，不能只靠逐帧硬堆或节点补间。
4. 可复用高于一次性装饰。Godot 原生形状可以作为临时替身，但 v0.3 的技术方向必须能替换为 Spine 或同级工具产出的动画。

## 动画工具链

v0.3 采用 **"sprite sheet AI 管线主线 + 程序化几何/shader 辅助"** 路线，目标 AI 化 90%+。详细规范见 [../art/animation_pipeline.md](../art/animation_pipeline.md) 和 [../art/pipeline/SKILL.md](../art/pipeline/SKILL.md)。

- 主角、敌人、Boss、武器图标、FX、UI 装饰：sprite sheet 形式产出，由 `/hatch-*` skill 经 AI 图像生成 + 确定性 Python 脚本完成
- Godot：用 `AnimatedSprite2D` + `SpriteFrames` 直接消费 sprite sheet；`AnimationTree`/状态机驱动玩法切换；shader 和 `_draw()` 程序化补强
- 不再使用 Spine / DragonBones / 任何骨骼运行时（不能被 AI agent 驱动）

v0.3 必须先做一个**管线技术探针**：

- 新增 `AnimatedActor` 包装层，让玩法脚本通过统一接口播放 `idle`、`run-right`、`dash`、`sword-attack-1`、`hurt` 等状态
- 攻击命中帧、FX 生成帧、收招可取消帧通过 `AnimatedSprite2D.frame_changed` 信号驱动，**误差锁死在同一 `_physics_process` tick**
- 跑通主角 `/hatch-player` 一次完整循环（base → idle → run-right → run-left 镜像 → contact sheet → AI QA → Godot 资源导入）作为管线探针
- 如果当前没有图像生成 API 配额或 GPU，先用 `ZHEWEI_IMAGEGEN_BACKEND=mock` 跑通管线骨架，AI 生图等具备条件后接入

## 画面规格

- 目标分辨率：`1280x720`。
- 摄像机基准：横版战斗时玩家位于画面左中到中部，展开俯视时房间结构必须完整可读。
- 碰撞可视约束：所有可站立平台必须有明确上沿；所有不可通过树干/根墙必须比背景更实。
- 灰盒替换比例：v0.3 完成后，主场景中不应再出现裸 `ColorRect` 方块承担角色、敌人或核心地形表现。
- 色彩结构：
  - 背景：低饱和冷绿、深青、雾灰，负责空间深度。
  - 可行走地形：树皮棕、苔绿、浅边缘光，负责交互可读性。
  - 主角：冷白、暗蓝灰、少量圣痕金，负责从背景中跳出。
  - 敌人：腐绿、暗红、断裂白线，负责危险识别。
  - 展开/锚率：青白坐标线、金色锚点、紫红侵蚀只作为风险强调。

## 资产清单

### 主角

v0.3 先做主角垂直切片，不要求全动作库，但要求动作方向正确、接口可扩展。

- `Body`：斗篷/长衣主体，竖向轮廓比当前方块更接近人形。
- `Head`：无脸面罩或头巾，避免需要五官细节。
- `ArmWeaponAnchor`：武器挂点，跟随朝向和攻击状态旋转。
- `Shadow`：地面影子，展开/坍缩时可缩放。
- `AnimationEventBridge`：动画事件桥接，用于命中帧、FX、脚步、收招窗口。
- 状态表现：
  - idle：轻微上下浮动或斗篷呼吸。
  - run：身体倾斜 + 脚部/衣摆摆动。
  - jump/fall：影子和身体分离感。
  - dash：残影或短线拖尾。
  - hurt：白闪/红闪 + 短暂后仰。
  - dead：去饱和、跪倒或压扁为坐标碎片。

主角 v0.3 最低动作集（任务图见 `docs/art/jobs/player_saint_v0.3.json`）：

| 动作 | 帧数 | 要求 |
| --- | --- | --- |
| `idle` | 6 | 可循环，斗篷/圣痕有微动 |
| `run-right` | 8 | 可循环，脚底接触点稳定 |
| `run-left` | 镜像 | 由 run-right 翻转衍生 |
| `jump-start` | 4 | 起跳压腿 + 离地 |
| `fall` | 4 | 下落姿态，可顺接 jump-start |
| `dash` | 4 | 24 FPS 高速，可叠加残影 shader |
| `sword-attack-1` | 6 | 横斩，命中帧第 3 帧 |
| `sword-attack-2` | 6 | 返斩或下劈，给连段留口 |
| `hurt` | 4 | 受击后仰 |
| `death` | 8 | 跪倒或碎成坐标片 |
| `unfold-enter` | 6 | 被压成平面/坐标锁定 |
| `unfold-loop` | 4 | 展开状态悬浮，可循环 |
| `unfold-exit` | 倒序 | 由 unfold-enter 倒放衍生 |

### 武器

首批武器仍按原设定保留 6 把，但 v0.3 的落地层级分三档：

| 武器 | v0.3 表现目标 | 后续玩法定位 |
| --- | --- | --- |
| 剑 | 必须可见、可挥动、有攻击弧、有命中特效 | 近战基础、冲刺连段、稳定清怪 |
| 矛 | 有图标和地面展示占位，可作为后续武器资源样例 | 长距离直刺、穿透、站位控制 |
| 弓 | 有图标和地面展示占位 | 远程蓄力、暴击、弱点标记 |
| 法杖 | 有图标和地面展示占位 | 术式弹幕、区域控制、展开收益 |
| 回旋刃 | 有图标和地面展示占位 | 返回轨迹、背击、空间重映射 |
| 圣铃 | 有图标和地面展示占位 | 召唤、反制、热度/锚率交互 |

剑的 v0.3 必做项：

- 剑作为主角 sprite sheet 的一部分绑定在腰间，攻击时由动画帧表现出鞘+挥砍轨迹（不独立 sprite sheet）
- 攻击弧用 shader 程序化绘制，颜色 `#E8E4D4` 半透明，淡入淡出快
- 攻击弧和命中盒方向一致：碰撞盒激活由 `AnimatedSprite2D.frame_changed` 信号触发（hit_start 帧）
- 命中时出现短促火花（shader）、伤害数字（HUD 文本）和轻微屏幕震动
- 展开状态下剑的朝向支持八方向：通过 shader 旋转攻击弧，sprite 仍是横向版本但 set_facing 可切换
- 至少有 `hit_start`、`hit_end`、`spawn_fx`、`recoverable` 事件接口（绑定在 `AnimatedSprite2D.frame_changed`）

武器框架建议：

- 武器视觉资产由 `/hatch-weapon` 生成（图标 64×64 + 攻击 FX sprite sheet）
- 新增 `game/data/weapons/*.cfg` 的视觉字段：`display_name`、`icon_key`、`accent_color`、`trail_color`、`fx_sprite_key`
- 玩家场景保留 `WeaponAnchor` 节点用于位置参考，但剑的视觉表现绑定在主角 sprite sheet 内
- 攻击命中盒激活由 `AnimatedSprite2D.frame_changed` 信号在 `hit_start` 事件帧触发；现有 `SwordAttack` 逻辑必须在 v0.3 内迁移到事件驱动
- v0.3 不做武器切换 UI，但数据和美术命名要允许后续扩展

### 敌人

现有假人敌人要从调试块升级为“薄林腐化物”：

- 轮廓：低矮、前倾、像树皮/兽形碎片拼成。
- 攻击预警：地面扇形/短线闪烁，不只靠颜色块。
- 受击：裂纹亮起、短暂压缩、碎屑飞出。
- 死亡：碎成纸片/树屑，保留 0.4 秒后淡出。
- 最低动作集：`idle`、`move`、`telegraph`、`attack`、`hurt`、`death`。

### 巨木薄林房间

场景要分层：

- 远景：薄雾、树影、被压平的枝叶，不参与碰撞。
- 中景：主要树干和枝台，和碰撞平台严格对齐。
- 前景：根须、叶片、遮挡边缘，透明度低，不能挡住战斗。
- 出口/撤离占位：先做成“坐标门”或“树皮裂隙”，为 v0.4 单局流程预留。
- 展开可读性：lane 线要融入美术，像切片坐标线，而不是纯调试线。

### HUD 与 UI

v0.3 只做战斗 HUD 的美术统一，不做完整菜单。

- HP：用短条或圣痕裂纹表示，不再像纯文本调试值。
- 热度：保留数字，但加环形/槽形表现，满时给 `1` 展开按钮提示。
- 锚率/侵蚀：颜色变化和轻微抖动要明确，但不能盖住战斗。
- 武器显示：左下或右下显示当前武器“剑”的小图标和攻击冷却反馈。
- 结算/商店等界面留到 v0.4 以后。

### FX

最小 FX 包：

- 剑挥砍弧：0.10-0.18 秒，淡入快、淡出快。
- 命中火花：方向跟随击退方向，持续 0.20-0.35 秒。
- 受击碎屑：小粒子或短线，不使用昂贵粒子数量。
- 冲刺残影：1-3 个半透明残影或线条。
- 展开边缘：过渡 overlay 已有，v0.3 需要把颜色和房间 lane 统一。

```text
game/art/

    weapons/               # /hatch-weapon 输出
    room_thinforest/       # /hatch-room 输出
    fx/                    # /hatch-fx 输出
  ui/                      # /hatch-ui 输出 + 程序化绘制资源
docs/art/
  animation_pipeline.md
  pipeline/SKILL.md
  pipeline/style_contract.json
  pipeline/identity_brief.md
  pipeline/prompts/
  jobs/                    # 任务图 JSON
  runs/                    # AI 生成中间产物（gitignore）
tools/art/                 # 管线 Python 脚本
game/scenes/weapons/
game/scripts/weapons/
game/scripts/actors/
game/scripts/animation/
```

实现原则：

- 主角/敌人/武器视觉表现统一通过 `AnimatedSprite2D` + `SpriteFrames` 消费 sprite sheet；玩法脚本只通过 `AnimatedActor` 包装层调用，永不直接读 `frame`。
- `AnimatedActor` 运行时从 `spritesheet.png` + `manifest.json` 构造 `SpriteFrames`；`anim.tres` 可作为工具输出和编辑器辅助，但不是 headless 测试的加载前提。
- 核心视觉节点命名稳定，后续替换资源时不改玩法脚本。
- 武器攻击逻辑和武器视觉分离：逻辑管命中盒激活（订阅 `frame_changed`），视觉管 sprite 帧 + shader 攻击弧。
- 动画事件和命中盒激活必须在同一 `_physics_process` tick 触发（通过信号桥接，不要写 `await get_tree().process_frame`）。
- 所有新增视觉效果要有开关或生命周期，避免节点越积越多。
- 任何影响碰撞的地形美术必须对齐已有 `StaticBody2D`，不在美术节点里偷偷改规则。
- AI 生成的 sprite sheet 必须先通过 `tools/art/validate_atlas.py`，否则不允许进入 `game/art/sprites/`。

## Agent 切分建议

下一轮采用"1 + 3 + 1"结构：1 个管线建设 agent 在前，3 个内容生成 task 并行，1 个集成 agent 收尾。所有内容生成 task 都跑同一套 [../art/pipeline/SKILL.md](../art/pipeline/SKILL.md)，差别只在任务图 JSON。

### 阶段 1：管线建设（顺序前置，1 个 agent）

| Agent | 分支建议 | 负责范围 | 主要文件 |
| --- | --- | --- | --- |
| P | `feat/v0-3-art-pipeline` | 美术管线建设：style contract、identity brief、prompt 模板、tools/art 脚本、AnimatedActor 包装层、SKILL.md、初版 godot_import.py 验证 | `docs/art/pipeline/*`、`tools/art/*`、`game/scripts/actors/animated_actor.gd`、`game/scripts/animation/animation_event_bridge.gd` |

完成标准：

- `python3 tools/art/prepare_run.py --backend mock --subject player_saint --version v0.3` 跑通
- mock 输出能被 `compose_atlas.py`、`validate_atlas.py`、`make_contact_sheet.py`、`render_animation_previews.py`、`godot_import.py` 全部消费
- `AnimatedActor` 接口在 Godot 中可调用、`frame_changed` 信号能触发命中盒激活
- 文档自检：[../art/animation_pipeline.md](../art/animation_pipeline.md) 和 [../art/pipeline/SKILL.md](../art/pipeline/SKILL.md) 互相链接、术语一致

### 阶段 2：内容生成（并行，3 个 task）

阶段 1 通过后，下列 3 个 task **可独立并行**，每个 task 都是"准备任务图 JSON + 跑 /hatch-* + AI 视觉 QA 闭环 + Godot 资源接入"的同套流程：

| Task | 分支建议 | 任务图 | hatch 命令 | 输出 |
| --- | --- | --- | --- | --- |
| H1 主角 | `feat/v0-3-hatch-player` | `docs/art/jobs/player_saint_v0.3.json` | `/hatch-player player_saint` | `game/art/sprites/player_saint/`、`game/scenes/player/Player.tscn` 集成 |
| H2 敌人 + Boss | `feat/v0-3-hatch-enemy` | `docs/art/jobs/enemy_bark_corrupt_v0.3.json`、`docs/art/jobs/boss_thinforest_deer_v0.3.json` | `/hatch-enemy enemy_bark_corrupt`、`/hatch-boss boss_thinforest_deer` | `game/art/sprites/enemy_bark_corrupt/`、`game/art/sprites/boss_thinforest_deer/`、敌人场景集成 |
| H3 场景 + UI + FX | `feat/v0-3-hatch-environment` | `docs/art/jobs/room_thinforest_v0.3.json`、`docs/art/jobs/hud_v0.3.json`、`docs/art/jobs/fx_sword_v0.3.json` | `/hatch-room room_thinforest`、`/hatch-ui hud_v0.3`、`/hatch-fx sword_arc` | 房间分层背景、HUD 装饰、剑气 sprite + shader |

每个 task 的标准流程：

1. 写/审 任务图 JSON
2. 跑 `/hatch-*`（或本地等价命令）：base → 全 row → contact sheet → AI 视觉 QA
3. 视觉 QA 不通过 → 修复循环（每次最多 5 轮，5 轮不收敛升级到人工介入）
4. 视觉 QA 通过 → `godot_import.py` 自动产 `spritesheet.png`、`manifest.json` 和可选 `anim.tres`
5. 接入对应 Godot 场景（替换占位 ColorRect/Polygon2D）
6. 提交分支 + PR：附带 contact sheet 截图、预览 GIF、QA review.json

### 阶段 3：集成与验收（顺序收尾，1 个 agent）

| Agent | 分支建议 | 负责范围 | 主要文件 |
| --- | --- | --- | --- |
| I | `feat/v0-3-integration` | 合并 H1/H2/H3，统一风格抽检，验收清单逐项过，录制 20 秒战斗片段 | `game/scenes/main/Main.tscn`、`docs/iterations/v0.3_art_weapon_vertical_slice.md`（更新已知问题清单） |

### 冲突提醒

- P 必须先合入或至少冻结接口（`AnimatedActor`、`AnimationEventBridge`、`SpriteFrames` 命名规范），H1/H2/H3 才能开始
- H1/H2/H3 之间唯一可能的冲突在 `game/scenes/main/Main.tscn`——三个 task 都不直接改主场景，所有 sprite 接入通过修改各自的 actor 场景文件（`Player.tscn`、`DummyEnemy.tscn` 等）。主场景由 I 阶段统一接入
- HUD（H3 的子任务）不改玩家攻击逻辑；如需要当前武器信息，通过 P 暴露只读接口读取
- 任何 task 不修改 `docs/art/pipeline/style_contract.json` 或 `identity_brief.md`——这两个文件锁定后由 P 单独维护，task 只通过 prompt overrides 微调
- 任务图 JSON 在各自 task 内编写，但 schema 由 P 锁定；不允许任意添加新字段

## 验收标准

必须通过：

- `python3 tools/verify_scaffold.py`
- `python3 tools/art/validate_atlas.py` 在主角 atlas 上通过
- `godot4 --headless --path . --quit`
- 已有 smoke tests 不因纯美术改动失败
- 至少 1 个 subject（主角）的 `/hatch-*` 完整跑通过 AI 视觉 QA（`visual_qa=pass`）

人工验收：

- 打开主场景后，第一眼能看出主角、敌人、地形、武器和 HUD 分属不同信息层
- 录制 20 秒战斗片段，包含跑动、跳跃、冲刺、两段剑击、受击、展开、坍缩，动作不能明显卡顿
- 鼠标左键攻击时能看到剑挥动和挥砍弧，命中位置与伤害反馈一致
- 剑的视觉、攻击弧、命中盒方向一致
- 按 `1` 展开后，lane/落点提示不再像临时调试线，而像世界规则的一部分
- 玩家受击、敌人受击、冲刺、坍缩都有短反馈
- 1280x720 截图中没有角色/武器/HUD 文本明显重叠
- 跨 subject 风格一致性（contact sheet 抽检：主角、敌人、Boss 看起来像同一个世界的角色）

暂不验收：

- 6 把武器的完整战斗机制。
