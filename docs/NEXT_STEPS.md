# Demo v0 下一步计划

当前工程已经有 Godot 项目骨架、主场景、玩家、基础攻击、假人敌人、平面展开状态机、HUD 和巨木薄林测试房。下一步应该先从“能在 Godot 里稳定跑起来”进入“有统一美术和可见武器的垂直切片”，再继续做 3 分钟单局流程。

## P0：Windows/Godot 首次实机验收

目标：确认工程能在 Godot 4.x 中打开、运行、输入正常响应。

验收项：

- Godot 可以导入 `project.godot`。
- `F5` 后进入 `game/scenes/main/Main.tscn`。
- 玩家可移动、跳跃、冲刺。
- 鼠标左键可攻击假人敌人。
- HUD 显示生命、圣痕热度、锚率、展开状态。
- 热度满后按 `1` 可以进入展开状态，再按 `1` 可以提前坍缩。

完成 P0 前，不建议继续扩大内容量。先把运行时错误清干净。

## P1：可玩手感最小闭环

目标：让单房间战斗不再只是技术连通，而是能判断手感方向。

建议任务：

- 加玩家受击无敌、闪烁反馈、死亡输入锁定。
- 加敌人基础巡逻、追踪、攻击前摇和可打断窗口。
- 加命中停顿、轻量屏幕震动、击退衰减。
- 加简易相机跟随和房间边界限制。
- 给攻击命中、受击、死亡添加临时音效占位。

验收项：

- 玩家能和 2-3 个敌人打一场完整小战斗。
- 受击原因清楚，不出现无预警秒杀感。
- 攻击命中有明确反馈。

## P2：平面展开表现闭环

目标：让核心卖点可被玩家看懂。

建议任务：

- 展开前显示短暂时停和画面拉伸/压平过渡。
- 展开期间切换到俯视移动规则，并限制跳跃。
- 显示 lane/落点预览或落点反馈。
- 坍缩时把敌人吸附到合法地面点，并显示风险变化。
- HUD 对锚率变化做颜色和数字反馈。

验收项：

- 第一次使用展开时，玩家能理解“空间规则变了”。
- 坍缩后的角色和敌人位置合理，不穿墙、不悬空。

## P3：美术与武器垂直切片

目标：解决当前 demo 灰盒感太重、武器不可见的问题。

建议任务：

- 制定第一版美术规范、调色板、动画工具链、资源目录。
- 评估并接入 Spine 2D + spine-godot 的技术探针；如果暂时阻塞，先做同接口 Godot 原生替身。
- 替换玩家方块，加入基础人形轮廓、影子、冲刺/受击/死亡反馈。
- 加入 `WeaponAnchor` 和剑的可见模型、挥砍弧、命中特效。
- 为矛、弓、法杖、回旋刃、圣铃建立图标或展示占位。
- 替换巨木薄林主要灰盒地形，统一背景、平台、lane 提示、出口占位。
- 美术化 HUD，加入当前武器槽。

验收项：

- 主场景截图看起来像一个游戏切片，而不是调试房。
- 20 秒战斗录像中主角和剑的动画流畅，不出现明显卡帧、脚滑、武器漂移。
- 鼠标左键攻击时能看见剑和攻击弧。
- 展开时的 lane/落点提示和房间视觉风格一致。

详细方案见：[iterations/v0.3_art_weapon_vertical_slice.md](iterations/v0.3_art_weapon_vertical_slice.md)。

## P4：单房间目标与撤离

目标：给 demo 一个明确开始和结束。

建议任务：

- 房间进入后锁门。
- 击败敌人后生成撤离点。
- `E` 交互撤离，进入简易结算界面。
- 结算展示本局圣痕点、锚率变化、击杀数、展开次数。

验收项：

- 玩家能从开始、战斗、展开、撤离、结算走完一次 3 分钟流程。

## P5：内容扩展前的工程整理

目标：为下一批 agent 并行开发降低冲突。

建议任务：

- 拆分可配置数据：武器、敌人、房间、掉落。
- 增加 Godot 运行检查脚本或最小自动化 smoke test。
- 制定 PR 验收模板：运行截图、测试步骤、已知问题。
- 确定 Demo v0 只支持一把武器还是先接入两把武器。

验收项：

- 新 agent 可以在独立分支上添加敌人、道具或房间，不需要改核心脚本。
